# Third-Party Licenses

OpenBNCT does not vendor third-party source, transport engines, nuclear data,
or patient data. Rust packages are resolved from crates.io and locked by the
committed `Cargo.lock`.

Release archives (desktop binaries), the web build published to GitHub
Pages, and the Python wheels/sdist each ship a `THIRD_PARTY_NOTICES.txt`
generated by `scripts/third_party_notices.py`. That script walks the
`cargo metadata` resolve graph from the shipped binaries' crates over normal
(non-dev, non-build) dependency edges and bundles the full license/notice
text found in every third-party package's published source — it is
regenerated from `Cargo.lock` on every release rather than hand-maintained,
so it cannot drift the way the table below can. Run it yourself with:

```
python3 scripts/third_party_notices.py --output THIRD_PARTY_NOTICES.txt \
  --extra "Noto Sans CJK JP (subset)=crates/openbnct-gui/assets/NotoSansCJKjp-UI.LICENSE.txt"
```

or, for the Python bindings' own (smaller) dependency set, with
`--manifest-path bindings/python/Cargo.toml`.

substitute for the generated bundle — it does not show transitive
dependencies (e.g. egui's bundled fonts, below) and its versions drift as

The GUI (`crates/openbnct-gui`, desktop and web builds) also embeds, as data
rather than crate dependencies:

- A glyph subset of Noto Sans CJK JP covering the GUI's Japanese strings
  (SIL Open Font License 1.1; copyright Adobe, Reserved Font Name "Source").
  The subset and its license text live at
  `crates/openbnct-gui/assets/NotoSansCJKjp-UI.otf` and
  `crates/openbnct-gui/assets/NotoSansCJKjp-UI.LICENSE.txt`, and are
  regenerated by `crates/openbnct-gui/assets/regen-cjk-font.sh`.
- egui's built-in default fonts, pulled in transitively through `eframe` via
  the `epaint_default_fonts` crate (license expression
  `(MIT OR Apache-2.0) AND OFL-1.1 AND Ubuntu-font-1.0`; the OFL and Ubuntu
  Font Licence texts for those fonts live inside that crate's own source and
  are included verbatim in the generated `THIRD_PARTY_NOTICES.txt`).

CI installs, but does not vendor, link, or redistribute, dicom3tools snapshot
`20240118131615` under BSD-3-Clause solely to run `dciodvfy` and `dcentvfy` as
independent DICOM validation tools.

The optional nuclear-data inspection script requires a user-supplied Python,
NumPy (BSD-3-Clause and compatible notices), h5py (BSD-3-Clause), and HDF5
(BSD-style) environment. Its Python packages are pinned in a dedicated
requirements file, and all exact runtime versions are recorded in every
generated manifest; they are not bundled by OpenBNCT.

OpenMC is a planned external transport backend and is not part of OpenBNCT.
OpenBNCT's acquisition client does not redistribute OpenMC or nuclear data;
users remain responsible for obtaining and validating the external engine and
data libraries used by their calculations.
